# 导航 Harness 架构草案

本文仅约定支撑[项目架构](Architecture.md)的运行方式与接口边界。工具拆分、空间表示字段和上下文策略尚未定稿，不作为已实现能力。

## 1. 当前设定

- 输入：任务目标、RGB-D、持续提供的位姿，以及仅包含墙壁和可通行区域的基础平面图。
- 输出：模型自主调用导航工具，最终通过原子动作驱动环境。
- 外部记忆：模型可逐步补充房间、物体、空间关系和证据；基础图与环境提供的位姿不由模型改写。
- 任务范围：ObjectNav、指令导航与 GOAT 式连续多目标导航，共用运行循环，通过任务适配器处理目标和结束规则。

模型可以连续查询后再移动，也可以移动后补充观察和记忆。能力分类不规定固定的“定位—规划—移动”阶段顺序。

## 2. 三层分工

| 层 | 负责什么 | 对外边界 |
|---|---|---|
| Agent runtime | 调用模型、分发工具、追加上下文、触发压缩 | 接收初始消息和工具集合，不直接操作 Habitat |
| 导航会话 `NavigationSession` | 连接工具、环境、地图、空间记忆和证据，管理一次运行 | 工具调用 → 文本／图片结果与执行反馈 |
| Environment | 产生观测、执行原子动作、推进任务、提供私有评分 | 公开观测与任务变化；评分另交评估器 |

教师与学生使用同一导航会话和执行规则。替换模型或 runtime 不应改变动作控制能力和信息开放范围。

## 3. 一次任务如何运行

1. **初始化。** 根据 Episode 创建环境，载入基础图，建立空间记忆与证据目录；取得当前 RGB-D、位姿和公开目标，交给 runtime。
2. **自主交互。** 模型决定查询、观察、更新记忆、移动或申请完成。会话执行工具，返回结果；runtime 将结果追加到上下文，再请求模型。
3. **反馈与修订。** 移动返回实际执行步数、碰撞等反馈及新观测。记忆更新记录证据和版本，模型据此继续决策。拟执行动作和执行结果分别保存。
4. **目标切换或结束。** 模型申请完成当前目标，环境按对应 benchmark 规则结算。连续目标任务可在同一位置继续下一目标，保留空间记忆；整个 episode 结束才关闭会话。超时与预算耗尽也由明确规则处理。
5. **记录与评分。** 保存模型实际输入、输出、工具结果和记忆变化，供训练与回放使用。成功率等私有指标不作为当前导航的工具反馈。

## 4. 暂定工具能力

| 能力 | 输入 → 输出／效果 |
|---|---|
| 观察与检查 | 当前帧或已获得证据的引用 → 图像、局部细节或深度信息；改变观察位置需要实际动作 |
| 查看地图 | 范围、图层等请求 → 基础图＋当前位姿＋已记录空间内容 |
| 查询记忆 | 目标、实体或区域条件 → 已记录内容及证据帧 |
| 修订记忆 | 实体、关系或区域的修改＋证据引用 → 新版本与更新结果 |
| 执行动作 | 原子动作或有上限的动作序列 → 实际执行反馈＋新观测 |
| 申请完成 | 当前目标的完成请求 → 任务结束或下一目标的公开信息 |

这些是接口能力分组，不是最终工具名称；查询与修订是否合并、是否提供地图路径查询，后续再定。第一版不引入像素目标到全局 navmesh follower 的自动行走。

## 5. 记忆与上下文

**对话上下文**由 runtime 管理，优先采用增量追加，达到预算后压缩；旧图片可按配置成批裁剪，避免每轮重组全部历史。裁剪会改变请求前缀，缓存命中需实际测量，不能只凭“保留最近几轮”保证加速。

**空间记忆**独立持久保存。对话压缩不删除空间实体或证据文件；模型通过工具按需读取。GOAT 切换目标时保留空间记忆，具体对话裁剪方式单独配置。

具体框架、压缩阈值、房间／物体表示和地图渲染方式后续确定。当前先保证同一套工具能被不同 runtime 调用，且每次模型决策的实际输入可还原为训练样本。
