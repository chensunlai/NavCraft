# 构建并复查场景地图

交付可直接浏览、独立加载的完整场景文件夹。**原始几何、语义和 RGB-D 是参考证据；最终平面图是经过理解、简化和校正的示意图。** 墙用直线段／必要折线，家具优先用矩形或旋转 box，L 形用多个 box。允许小幅尺寸偏差，但不接受伪造连接、独立家具穿插、越墙或错层。

## 确认输入与输出

1. 从用户给出的场景 ID 或路径解析实际场景目录、数据集与 split。保留编号前缀，不预设所有场景都在 HM3D val；短 ID 有多个匹配时再澄清。
2. 以 `data/nas/scene_datasets` 为默认素材根目录，`data/scene_maps` 为默认输出根目录；用户指定其他根目录时服从用户。输出复用场景的完整相对子路径。两个根目录可能是符号链接，不要丢失逻辑目录层级。
3. 阅读 [归档格式](references/archive-format.md)。现有 NavCraft 仓库先按 [本地实现与取证](references/local-workflow.md) 检查可复用代码和实际依赖，不能直接假设旧三场景脚本支持任意新场景。
4. 用户指定几个场景就处理几个，遵守顺序和阶段范围。只要求墙体时停在墙体与楼梯，不提前生成房间／家具数据，也不提前检查后续批次。已有归档先保存相关旧数据与主图的版本；不改原始场景资产，不无意重建其他场景。
5. 构建或复查墙体时阅读 [墙体补全与楼梯交付](references/wall-completion.md)。默认 wall 包含实体墙、围栏、场景边界及缺失补全；另存估计前有实际证据的 wall_real。逐场景任务必须完成当前场景验收后再切换。

每个场景顶层严格为：

```text
<dataset>/<split>/<scene>/
├── floor_plan.png
├── scene_description.md
├── evidence/
├── evidence_rooms.jpg
└── raw/
```

## 构建流程

### 1. 先建立空间与取证范围

检查 RGB 网格、语义、NavMesh、已有探索记录、相机参数和坐标。统一为米制 Habitat 水平 `(X,-Z)`、高度 `Y`；继承其他坐标系时显式转换。先识别实际楼层与入口平台，再处理二维投影；不得将上下层投影取并集。

先看整层概览，再获取房间内部、入口两侧、楼梯上下端的第一视角。已有人类式示意图和文字可辅助理解，但不能当作无需复核的真值。语义标签和 NavMesh 只提供证据，前者可能误标，后者不能直接充当墙体或真实门宽。

### 2. 建立有依据的结构与物体

- 分别维护墙段、开口、房间／功能区、楼梯与主要物体。分区边界不自动成为墙；开放客餐厨保留开放关系。
- 为每个房间确认入口、连接对象和状态。门扇、门洞、门楣分别识别，活动门扇不作为永久墙。围栏也是阻挡墙，不能仅画成辅助虚线。楼梯记录上下层、范围、踏步、平台和上下行箭头；墙体阶段独立保存，完整地图阶段再关联分区。
- **灰区、空白区、断开的房间先去看。** 沿外围找入口，补看内部或相邻侧，核对高度、地面与路径；先取证，再按墙体补全规则选定具体边界；不能用未知标签代替检查。非墙体信息或仅观测模式可以保留具体未知。
- 对家具参考主体几何、多个视角及高度关系，绘制简化 box。不要将实例全高度 AABB 直接当足迹，尤其是 L 形沙发、椅背、台面、镜面和墙挂物。物体名称不确定时注明，而不是靠规则猜类别。
- 缺损墙与场景边界允许合理估计，最终 wall 选定明确几何、统一实线；依据与估计来源保留在数据中，wall_real 排除补全段。不得把推断升级成实测，也不得为闭合而封住真实开口或为连通凭空开门。

### 3. 关联文本、图片和图层

按用户要求的阶段关联内容。墙体阶段仅保存结构／楼梯说明、证据和双墙图层；完整地图阶段为每个房间写功能、主要视觉特征、布局、物体关系、入口与连接、未确认部分；每个主要物体都关联实际可读的证据帧，不能用一张房间图冒充所有物体都已确认。补齐房间／楼梯代表图 `evidence_rooms.jpg`，物体证据按房间可另做联系表。

帧 ID 带来源命名空间，保留相机信息及原始帧号。区分真实探索与离线渲染；同号帧不能跨 run 混用。只有实际检查后才能声称物体可见；语义像素存在也不是类别正确的充分证明。

所有正文、图层、对象与证据通过稳定 ID 关联。墙体、分区、物体各自保存源数据与独立图层；不要只交一张合成 PNG。

### 4. 多轮复查与矫正

开始检查前阅读 [复查清单](references/review-checklist.md)，逐项留下结论与证据。

- **第一轮：结构与覆盖。** 逐房间、逐入口、逐未知区、逐楼梯检查，渲染确认真实连接。核对原始路径是否被示意墙错误阻断。
- **第二轮：几何与语义。** 对整层检查墙段接缝、门洞穿透重复墙、分区重叠、家具错位／越界／相互穿插；回看触发问题的 RGB，修正源数据后再绘图。不要通过自动缩小所有 box 或扩大所有房间来消除错误。
- **第三轮：修改后的整体验收。** 重新打开最终 PNG 和局部放大图，复核修改处与相邻房间，重跑几何／引用检查。不能拿修改前的检查结果作为最终版本结论。

三轮是推荐组织方式，不要求每轮重采全部素材；有新错误继续针对性取证。重要的是至少经历“初检→有依据的修改→对最终结果复检”。墙体取证无新增信息时，按补全规则采用合理估计并保留来源，不能反复取证后只留下问号便交付。仅观测模式或其他未完成阶段保留具体未决项与 partial；若关键几何仍未决定，不宣称验收通过。

### 5. 归档与交付

先在工作目录完成修正，再更新用户指定场景。把完整证据图片复制到归档，不能依赖临时 cache 或旧 runs 才能打开。同步图、JSON、描述、连接图、帧关联、索引与校验和。顶层保持五项。

完整地图使用下列只读脚本检查文件结构、引用、box 与几何关系；使用装有 Shapely 的 Python。该脚本要求 rooms/regions/objects，不适用于仅墙体阶段；仅墙体阶段按 [墙体验收](references/wall-completion.md) 检查双图层、楼梯、引用与校验和，记录实际执行结果，不能制造空房间／物体文件来通过完整地图校验。

```bash
python <skill-dir>/scripts/validate_archive.py <scene-directory>
```

脚本不验证 RGB 事实或真实可达性，不能代替渲染复查。路径局部连通、整图连接图、实际动作执行分别报告，不能把 NavMesh 查询说成代理已走通。真实不可达房间允许保留已核实的关闭／阻断状态，不能为了通过检查强制所有节点连通。

交付时提供主图、场景目录／描述链接，以及本轮修正和剩余问题。只有完成视觉复查且所有关键错误已解决，才标记 reviewed；文件可读、JSON 有效或图更漂亮都不代表地图正确。
