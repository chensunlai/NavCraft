# 研究汇报与近期计划

更新：2026-10-13。项目实现见 [Architecture.md](Architecture.md)，训练数据见 [Tasks.md](Tasks.md)，实验与协议见 [Experiments.md](Experiments.md)。

<a id="motivation"></a>
## 1. 研究主线

**目标是训练能够利用地图、记忆和导航工具完成多类导航任务的模型，并交付可运行的通用 Harness。** 当前重点是导航相关空间能力的学习，教师模型用于生成与诊断，不作为独立研究主线。

论文逻辑可以归纳为四步：

1. **通用空间判断与实际导航存在差距。** 导航中的空间理解更具目标针对性，还需跨视角、跨动作持续一致：将观察对应到地图，选择通路，把路线落实为动作，并根据新证据修正判断。
2. **工具和记忆提供条件，模型还需要学会使用。** 有地图、有历史，不等于能在合适时机检索证据、发现错误并改变行动；空间 QA 正确也不保证执行正确。
3. **完整轨迹训练可以学到这些能力，但通常给予间接约束。** 同一个正确转向可能依赖位置、目标方向或门的连通关系，仅匹配教师行为不能单独说明哪项判断被可靠掌握。明确空间监督能否提供额外收益，需要实验回答。
4. **因此，将导航所需空间判断及其对行动的作用作为针对性训练内容。** Harness 提供统一交互条件，训练覆盖静态判断、检索、主动感知和局部执行，最终以完整导航验证收益。

**工作假设：在相同训练预算下，明确监督导航空间判断、证据关联和空间—行动一致性，能够比仅模仿完整交互轨迹更有效地改善导航。** 这是假设，不能预先写成“轨迹训练只会模仿”。如果完整轨迹已经包含充分、可核验的空间监督，它也在训练这些能力；将轨迹切短或改成 QA 并不自动构成方法创新。

预期贡献应落在**有效的空间能力训练方法、模型自主组织工具的通用 Harness，以及受控的跨任务导航收益**。地图、工具、阶段相关空间训练均有先例，单独新增数据集不足以支撑这条主线。后续 RL／OPD 可用于完整交互优化，需与前阶段收益分开验证。

## 2. 直接相关证据与已有工作

以下沿用 2026-10-12 已完成的文献核查；数字仅适用于链接版本及其各自实验条件，不跨论文比较成功率。

| 工作与来源 | 与本项目直接相关的结果 | 对研究定位的约束 |
|---|---|---|
| [Spatial-Nav，Tables 2–4](https://arxiv.org/html/2609.29934v1) | 基础／通用描述／目标相关空间监督 SR 为 59.2／59.5／62.1%；决策监督 59.6%，空间与决策分别监督 65.5%，串联推理与决策 59.4% | 已研究目标与阶段相关空间训练；支持研究监督形式，但不是完整工具轨迹 SFT 的等预算对照 |
| [VLN-MME，§4.3、E.2](https://arxiv.org/html/2512.24851v1) | 文本地图 Agent 的 200 条轨迹中，131 条导航错误里有 106 条循环，历史通常未超出上下文容量 | 历史可用不保证有效纠错；错误统计不能证明某种训练方式造成失败 |
| [NavSpace，Table I、§VI](https://arxiv.org/html/2510.08173v1) | 定性案例中存在空间问题回答正确、行动却不一致，以及跨帧判断矛盾 | 静态 QA 不能替代交互验证；该解释主要来自案例分析 |
| [NavHarness，Table 12](https://arxiv.org/html/2609.34276v1) | GOAT 上主动／固定历史访问的 s-SR 为 81.5±0.7／74.5±0.8%，覆盖 360 episodes、2,669 subtasks、三次运行 | 持续导航和主动记忆已有先例；消融同时改变查询时机、选择与后续轨迹，不单独证明训练有效 |
| [HarnessVLN，Table 4](https://arxiv.org/html/2609.15195v1) | 固定 100 episode 子集，累加事件记忆、图检索、停止验证后，R2R SR 为 46→54→60→64% | 通用 Harness 已有先例；累加消融的增益依赖先前组件，不能归因于单个能力 |
| [SpaceVLN，方法与附录 C.1](https://arxiv.org/html/2606.08992v1) | 在线维护度量地图、区域与地标证据，并分阶段规划执行；使用 RGB-D 和持续位姿 | 在线空间表示本身也非空白；与本项目比较需明确传感器和定位条件 |
| [AgenticNav v3，Tables III–IV](https://arxiv.org/html/2606.10577v3) | 固定 R2R-CE 设置：完整系统 76%，累积所有历史图像 66%，移除 Recall 64% | 上下文和证据接口影响表现，不能将接口差异直接解释为模型空间能力差异 |
| [CorrectNav，Table 2](https://arxiv.org/html/2508.10416v1) | 首轮纠错训练完整方法 63.0%，移除关键帧感知 60.1%，移除轨迹纠正 59.2% | 已有针对导航感知和行动的联合训练；纠错数据与监督变化需分别控制 |

**比较协议需单独核验。** [BSC-Nav 的配置覆盖](https://github.com/Heathcliff-saku/BSC-Nav/blob/ad4c544f7d1feb980ffad33d4eefa8ad2e39fad0/env.py#L552)和 [OmniNav 快系统配置](https://github.com/amap-cvlab/OmniNav/blob/e8b485953c6555e841a3283c3e3a4f7d8d0f24c3/infer_ovon/ovon/configs/ovon_pano.yaml#L32)提供成功视点 1 m 的实现先例，但不能把它当作所有工作的统一协议。NavHarness 主表成功半径尚未核实；扩展部署的 1 m 不能替代主表配置。协议、动作和定位条件的完整口径见 [Experiments.md](Experiments.md)。

## 3. 当前证据能说明什么

当前已有视觉 Harness、原子任务展示和少量开发轨迹，尚未建立训练收益结论。开发中观察到反复碰撞、位置标记长期不更新、旧摘要错误延续，以及连续目标切换后缺少重新验证。这些现象为任务和诊断提供切入点；具体数字、原始轨迹及已修复工程缺陷统一保存在 [实验记录](Experiments.md)。

归因时先排除 API、工具输出、地图、上下文压缩和评分协议问题。少量开发案例不能形成模型排名；显式地图未更新也不等于模型没有内部定位。原子数据展示证明的是数据形态和执行可核验性，不能代表教师自动生成稳定、模型泛化或训练有效。

## 4. 近期执行顺序与验证

| 阶段 | 要完成什么 | 推进条件 |
|---|---|---|
| 稳定 Harness | 固定输入、工具、记忆和评分条件；在选定任务上收集完整教师交互，区分工程故障与导航失败 | 能稳定重放、定位错误，接口与日志可信 |
| 建立轨迹 SFT 基线 | 尽早用教师完整导航轨迹训练小模型，在同一 Harness 下评估 | 明确轨迹训练已能解决什么、还剩哪些稳定缺陷 |
| 加入空间操作训练 | 从地图—观察对齐、证据使用或行动修正中选择一两类，使用可核验数据训练 | 在未见场景的完整导航中获得可重复收益，再扩大任务范围 |

核心对照从**同一轨迹 SFT 检查点**出发：一组继续完整轨迹训练，另一组增加针对性空间监督；对齐训练预算、教师与场景来源、Harness 和评估条件。保留基线全部可导出的教师回答及工具调用，不通过删掉空间信息弱化基线。

若方法新增纠错轨迹、交互状态或教师调用，还需提供相应数据／预算对照，区分数据覆盖与监督方法的收益。RL／OPD 加入后再做独立消融，避免全部收益混在一起。

验收同时看两层：

- **完整导航：**目标搜索、指令跟随、连续目标的成功率、路径效率、成本与错误恢复，记录统一输入和判据。
- **行为诊断：**空间证据改变时，模型是否调整检索、位置判断和行动；碰撞是否触发修正；目标切换是否重新验证实例与到达条件。

原子任务分数提高用于解释能力变化，不能替代完整导航收益。先用小规模基线验证方向，再投入大规模数据和训练。
