# 空间记忆：平面图、文本与证据图片

归档：2026-10-14。本文定义目标 Harness 的空间记忆形式、关联与读写边界，供工具和数据集设计使用。设计以导航中的信息使用需求为依据。

三种记忆是 **平面图、文本、证据图片**。场景资料、运行记录和模型判断是来源与权限分类，不是另外三种记忆。上下文的增量追加、预算触发压缩与缓存策略见 [Harness 上下文管理](Architecture.md#context-management)，不在本文重复定义。

## 1. 三种形式及逻辑文件

| 形式 | 作用 | 目标文件形式 |
|---|---|---|
| 平面图 | 表达区域、结构、物体的位置与布局 | 只读基础墙层＋当前实体图元；按需渲染带 ID 的 PNG |
| 文本 | 解释实体语义、关系，以及模型当前的判断和计划 | 按实体组织的 Markdown 卡片＋`state.json`＋补充笔记 |
| 证据图片 | 提供可以重新查看的真实视觉依据 | 原始 RGB＋轻量图片索引；裁剪／拼图保留来源 |

以下目录只是目标组织方式，不表示这些文件已在仓库中生成：

```text
scene/                         # 任务提供的初始资料，只读
  index.md                    # 地图入口、坐标约定、初始资料来源
  maps/L1.base.png             # 干净的基础墙层，保留开口
  initial/                    # 可选：允许提供的预建图元与卡片
  evidence/                   # 可选：允许提供的历史证据与索引
observations/                  # Harness 追加的运行 RGB 与索引
memory/                        # 模型可编辑
  maps/L1.entities.json        # 唯一当前房间／出入口／物体图元
  entities/D03.md              # 唯一当前实体卡片，允许新建
  state.json                  # 当前估计与局部计划
  notes.md                    # 可选：其余值得保留的笔记与经验
scratch/                       # 脚本、派生图像与计算产物
```

**初始资料与当前记忆分开，当前实体只维护一套。** 任务提供预建实体时，将获准图元和卡片初始化到 `memory/`；只给墙图时，实体表从空开始。初始化是复制公开资料，不根据模拟器隐藏标注补齐实体。后续检索和绘图以 `memory/` 为当前记录，`scene/initial/` 仅供追溯；删除或修订后不能从初始资料自动恢复旧实体。任务可限制给定实体的改动，但不需要另一套表示。

仅提供地图图片的题目不自动初始化其背后的实体 JSON；模型可以根据图片保存自己的估计。若没有单独提供干净墙层，原图作为只读参照，不为了重绘而访问隐藏图元；该任务是否开放 `render_map` 由公开工具范围决定。

## 2. 平面图：带 ID 的图像与对应图元

地图由**基础墙层＋当前实体图元＋位置估计**绘制，PNG 是这些记录的展示结果，不另行手绘一份正式地图。底图不能烘焙旧家具、房间标签或位置箭头，否则修订实体后会留下残影。每张图用 `map_id` 标识所属楼层与底图，实体 `id` 在同一场景中保持稳定，不能因裁剪或重新渲染而变化，删除后的 ID 不分配给另一实例。

| 元素 | 表达内容与边界 |
|---|---|
| 区域 `region` | 房间、走廊、开放功能区等范围；区域不一定封闭，区域分界不自动成为墙 |
| 墙体 `wall` | 基础层中的围合或分隔结构，保持只读；未知厚度时不假定精确厚度，显示线宽不是墙厚 |
| 出入口 `portal` | 门、门洞、开放连接的位置与开口范围；已知时记录所连区域，另一侧未知则保留未知 |
| 物体 `object` | 主要实例的近似俯视外形，可用一个 box 或几个简单形状组合；box 不等于精确占据范围 |
| 跨层连接 | 楼梯等以区域及出入口表示，引用已知端点的区域 ID 和楼层；缺少资料时不猜测另一层连接 |

当前实体记录至少包含 `id`、`map_id`、`type`、`geometry`。区域用多边形、开口用线段／折线、物体用 box 或多个简单形状；`type` 表示图元大类，名称、类别、所属／连接区域和证据放在对应卡片，避免分别维护两套关系。墙体使用任务提供的图片或获准图元，不加入可编辑实体表。

**`geometry: null` 表示已发现但尚未定位，不表示不存在。** 此时仍可按 ID 查询卡片和证据，绘图列出未定位实体但不猜测坐标；所属地图也未确定时先记入笔记，确认后再登记。空实体表表示尚无记录，不表示区域没有物体。构图允许只知道部分房间边界、门的一侧或物体的近似位置，不要求一次补齐。

**统一使用所属原始地图中的归一化坐标。** 左上角为 `[0, 0]`，右下角为 `[1, 1]`；box 为 `[left, top, right, bottom]`。裁剪和缩放保留到原图的映射，不改写图元坐标；不同 `map_id` 的数值不能直接比较。

地图入口公开 `map_id`、`base_ref`、`current_entities_ref`、原图 `width/height` 和坐标约定；例如 `map_L1` 指向 `scene/maps/L1.base.png` 与 `memory/maps/L1.entities.json`，工具按该映射读取，不猜文件名。比例尺仅在任务确实提供时给出。计算图上方向或距离时，先用原图尺寸将归一化坐标换为像素坐标，避免长宽比造成失真；只有有效比例尺才能换算为米。基础层和坐标约定不随模型修订而变化。

```json
[
  {"id":"D03","map_id":"map_L1","type":"portal","geometry":{"segment":[[0.42,0.31],[0.49,0.31]]}},
  {"id":"O12","map_id":"map_L1","type":"object","geometry":null}
]
```

以上坐标及下文样例均为**假设格式示例，不是场景新增标注或真实运行证据**。

图上空白不保证可通行；出入口的几何邻接、连接对象、开闭／阻挡状态和实际通过记录是不同信息。不能凭门的存在或一张入口图断定机器人可通过。新增 portal 不会自动在基础墙上开洞；怀疑墙图有误时记录冲突并查证，本设计不让模型改写给定墙体。

小物体无需全部绘制 box。桌上的杯子可先写入桌子的描述并引用证据，确需独立辨认或导航时再分配实体 ID。新观察先判断属于已知实例还是新实体，不因换视角重复建物体。布局或连接不确定的部分保留未知，不依据图上空白补全。

位置／朝向估计是**运行叠加标记**，由 `state.json` 提供，地图显示只是可视化；初始提示、模型估计和历史位置须区分。候选位置、计划路线等临时图示可按需绘制到 `scratch/`，不再维护第二份定位或计划状态。

## 3. 文本：实体卡片、状态与补充笔记

模型按内容选择保存位置：实体位置与形状写入当前图元，语义与关系写入对应卡片，当前定位与任务意图写入 `state.json`，其余值得保留的内容才写入可选的 `notes.md`。同一判断不要求复制到多个文件；只服务眼前一步的临时分析可以留在上下文中。

### 实体卡片

一个区域、物体或出入口对应一张当前卡片；主要字段是 **实体 ID、地图引用、所属／连接区域、描述、关系、证据引用和未确认内容**，模型更新另注明步骤与依据帧。地图引用可以指向尚无几何的实体记录。Markdown 采用固定的简短字段标签，自由描述不要求解析成另一份数据库。

区域描述用途、主要辨识线索与相关实体；物体描述类别、外观及所在区域；出入口描述外观、两端区域和可见状态。对象归属以物体卡的“所属区域”为准，连接以出入口卡的“连接”为准，不另维护需要同步的房间邻接表。未知端点可写“未知”；关系引用涉及的实体 ID，方向说明参考系。

```markdown
# D03：白色门框的出入口
- 地图：map_L1 中的 D03。
- 连接：R01 与 R03；门口当前是否受阻需结合新观察。
- 外观：白色门框，侧面邻近矮柜 O07。
- 关系：D03 位于 O07 的地图上侧；不等于机器人当前左侧。
- 证据：E_demo_01 中央门框；E_demo_02 左侧门框及 O07。
- 来源：scene/initial/entities/D03.md；运行中尚未重新核实。
- 未确认：仅凭现有图片，不能判断新的障碍是否影响通过。
```

卡片里的图片引用指向图片索引；图中位置可以用文字或图像坐标标记说明，不要求每张图都有精确框。初始化卡片保留原资料引用；模型后续修改同一张当前卡片，注明新证据与更新时间，不覆盖只读初始资料。当前卡片是模型正在使用的认识，不等于核验真值。

查当前实体时，从 `memory/maps/` 的实体表或 `memory/entities/` 目录找到 ID，再读 `memory/entities/<ID>.md`。因此新实体立即可检索，不必修改只读索引或另维护一份实体清单。回看初始卡片属于查历史来源，不能将其旧描述重新当作当前结论。

### `state.json`：当前估计与局部计划

状态文件保存模型希望持续使用的少量运行判断，不复制完整对话和场景资料。下例同样为假设示例：

```json
{
  "goal_id": "goal_demo_2", "at_step": 12,
  "pose_estimate": {
    "map_id": "map_L1", "at_frame": "f_demo_012",
    "position": [0.45, 0.38], "heading_point": [0.45, 0.31],
    "status": "tentative"
  },
  "subgoal": "确认眼前门口是否对应 D03，再进入 R03",
  "open_questions": ["f_demo_012 中央门是否为 D03？"],
  "evidence_refs": ["f_demo_012", "E_demo_01"]
}
```

`goal_id` 表示这份计划针对哪个任务，不能靠修改文件宣布任务切换或成功。连续目标切换后，环境认识与历史证据保留，旧 `subgoal` 和目标相关疑问不继续作为当前任务意图；模型据新目标更新状态，位置估计保持原有时刻含义。

`at_step` 是更新状态时的原子动作计数；`pose_estimate.at_frame` 指明估计对应哪张观察时的机体位姿，`evidence_refs` 则是判断依据，两者不必相同。后续移动不能自动将旧估计当作当前位置。

`position` 和 `heading_point` 都使用所属原始地图坐标；`heading_point` 是指向朝向的第二个点，不是角度。证据不足时位置估计可以为空，或保留明确的待核实状态，不填造精确位置。当前子目标是模型计划，不替代环境下发的正式任务。

### 当前卡片与笔记的修订

`memory/entities/<ID>.md` 同时容纳实体说明及当前对应判断，注明依据帧及步骤；`memory/notes.md` 保存不适合绑定单一实体的自由笔记。确定程度、局部检查范围和未观察部分可用自然语言说明，不要求维护判断编号、状态机或覆盖率栅格。以下是更新时可写入卡片的片段，不是另一份补充文件：

```markdown
# D03 当前观察记录
- 步骤：14；观察：f_demo_014。
- 判断：门框与 O07 的关系支持当前门口对应 D03。
- 待确认：门口机身净空是否足够。
- 证据：f_demo_014、E_demo_02。
```

发现错误时，模型通过文件编辑替换或删除旧判断，使当前文件保持简洁。通常使用基座 `write`／`edit`；脚本修改遵守同一权限并记录实际变化。历史版本供审计和训练回放，首版不提供模型运行期版本查询；重新查证使用公开的原始图片与动作记录。修改文本不自动修改实体几何或自身位置，模型按影响范围更新相应记录。

例如，先前将门框误认成 D03，新证据支持 D05：模型修正当前卡片中仍在使用的错误对应，并重新判断受它影响的位置和子目标；仅新增“这是 D05”不能消除旧记录的冲突。尚未确定位置时可保留空值或待核实状态，按需继续查证。

空间关系须区分地图方向、图片方向、机器人方向和物体自身方向。图片关系绑定具体帧，机器人关系绑定步骤，物体方向说明朝向约定。“怎么出房间”保存入口、连接和已知约束，具体转向／步数由当前观察与位置决定。

## 4. 证据图片：原始 RGB 与轻量索引

证据用于区域概览、物体辨识、出入口核对及空间关系检查。图片必须来自真实采集或模拟器渲染；原始 RGB 保留，裁剪、拼图及带标记图是可追溯的派生图片，不能替换原始证据。

| 索引字段 | 含义 |
|---|---|
| `id`、`path` | 稳定图片 ID 与可访问路径；重渲染或生成裁剪时使用新 ID |
| `source` | 预构建证据、运行观察或派生产物，区分来源 |
| `step` | 拍摄时的原子动作计数；历史资料未知时为空 |
| `view` | 已知观察条件：相对机体的水平角与俯仰角、可选全景组；未知时为空，不推造世界朝向 |
| `derived_from` | 裁剪／拼图来源图片 ID；原始图为空 |

假设的新观察索引如下；`right_degrees` 相对拍摄该组全景时的机体朝向，不是地图方向：

```json
{"id":"f_demo_014","path":"observations/f_demo_014.png","source":"observation","step":14,"view":{"panorama_id":"p_demo_014","right_degrees":60,"pitch_degrees":0},"derived_from":[]}
```

图片 ID 唯一，`step` 不唯一：同一步可以多次观察或采集全景，每张原始 RGB 都有自己的 frame ID。不能用动作计数代替帧标识。

`pitch_degrees` 以水平为零、向上为正；水平角以机体前方为零、向右为正。视角标签表达相机相对机体的已知设置，不提供真实地图朝向。动作索引按执行顺序关联请求动作、执行／碰撞／中断反馈及前后观察引用；模型可用文件工具按帧或步骤查询，不需要另设历史数据库。

回看、裁剪或拼图保留原观察的时刻与来源；重新打开图片的时间不改变证据的新旧。历史采集时刻未知时仍标为未知，不能用本次读取时间补齐。

例如 `f_demo_014` 可以记录为“步骤 14 的新 RGB”，不能由 Harness 自动标成“位于 R01、看到 D03”。**新观察的房间、实例和地图对应由模型判断**，写入状态或笔记；构造数据的真实位姿、语义和深度留在私有核验材料。

已有与新增证据的实体关联都保留在当前卡片的图片引用中；新增证据直接引用运行帧，无需复制到 `scene/evidence/`。图片索引只提供来源和访问方式，不再重复维护实体清单或语义关系。

单张图片只证明其可见内容，不能自动说明整个区域已检查。多张原图与不同视角可以共同支持一个判断；历史证据不要求都具备完整时序或拍摄位姿。

## 5. 三者如何关联与使用

```text
实体 D03
  ├─ 当前图元：map_L1 中的开口位置与范围 → 地图上显示 D03
  ├─ 当前卡片：外观、连接、关系 → 引用历史证据和运行帧
  └─ 证据：按图片 ID 查到原图 → 核对图中的门及周边线索

新观察 f_demo_014 → 模型判断已知／新实体 → 更新当前卡片／图元／位置估计
```

一个实体可关联多张图，一张图可支持多个实体；关系可以同时关联多个实体和证据。frame ID 指一次观察，实体 ID 指区域或实例，裁剪不产生新的实体身份。

从地图出发，可以按 ID 查描述和图片；从新观察出发，模型根据外观、周边物体和布局提出对应，再利用地图定位或选路。预先关联资料不等于已经解决当前定位，图像框与俯视 box 也不能直接数值换算。

三种形式分工为：**地图表达布局，文本表达语义与判断，图片提供视觉依据。** 实体 ID 和帧引用使资料可以相互查找；当前画面是否对应该实体、旧关系在新朝向下意味着什么，仍由模型判断。

## 6. 在线构建、使用与修订

构图范围是**在给定墙图上补充导航所需的区域、出入口、主要物体及其关系与证据**。定位、对象对应和几何估计仍由模型完成，不要求从零恢复墙体、生成稠密三维重建或精确占据图；RGB 与初始定位提示不能保证后续估计精确。

| 情况 | 模型保存什么 | 后续如何使用 |
|---|---|---|
| 新发现房间、门或物体 | 分配未使用的实体 ID，创建当前记录与卡片；位置不足时 `geometry: null` | 先按外观、关系和证据查询，确认位置后再落图 |
| 得到可信的观察—地图对应 | 写入估计区域／开口／box，卡片说明定位依据与未确认部分 | 绘图后对照实际观察，作为定位或选路依据；不当作自动核验真值 |
| 穿门、换视角或看到新证据 | 更新卡片的连接、可见状态和证据；需要时调整几何 | 区分“看到门”“判断相连”“实际通过”，未知端点不凭空补齐 |
| 发现错位或重复实体 | 修正图元；重复实体保留一个 ID，并更新受影响卡片与状态引用后删除多余记录 | 当前地图不再显示旧位置或重复对象；历史帧仍引用原记录时刻 |
| 环境可能变化 | 保存新观察时刻、当前判断及旧证据的适用限制；同一实例移动可保留 ID 并修订位置 | 一次没看到不等于物体消失，先区分遮挡、看错位置和真实变化 |

模型可自行选择“观察→暂记实体→定位后落图→再次观察修订→导航时使用”等操作组合，不强制每轮写图或先建完整地图再走。地图记录供后续决策即时读取，结束后才补出的地图不能作为已验证在线维护的证据。

构图使用 `write/edit/bash`，`render_map` 提供可视反馈；不新增一套实体增删改工具。字段和引用检查由同一套轻量规则完成：JSON 可读、ID 唯一、坐标有效、声明的卡片／图片／实体引用存在。检查不裁决空间事实，不从模拟器补正确位置；格式错误明确返回，不能静默恢复初始图或上一版图。文件可分次编辑，不要求复杂事务或每步必校验。

## 7. 来源、权限与版本

| 内容 | 写入与修订原则 |
|---|---|
| 基础墙图、初始实体资料、归档证据 | 只读来源；初始化仅复制任务允许的实体，不暴露隐藏语义或位姿 |
| 原始运行 RGB、实际动作与反馈 | Harness 追加，保留事实记录；模型可引用，不能改写 |
| 当前实体图元、卡片、模型状态与笔记 | 模型通过基座文件／命令工具保存当前内容，受任务声明的写入范围限制；trace／文件版本记录实际变化，模型不手工维护修订链 |
| 地图叠加、裁剪、拼图 | 从指定来源生成，保留来源版本；派生图像不成为第二份可编辑真值 |

初始真值位置提示只表示初始化信息，模型后续估计不能冒充真值。修改笔记不改写旧帧和旧动作；完整执行日志及私有评分保存在公开工作空间之外。压缩摘要是对话交接材料，不自动覆盖工作记忆。脚本和临时产物放入 `scratch/`，需持续使用的模型判断写入 `memory/`；文件与命令工具遵守相同权限。

同一表示支持预建地图使用和在线构图；差别是初始提供哪些内容、哪些记录允许修改。查询 QA 可以保存自己的推断，但外部资料库仍固定，不能借初始化或绘图补入未公开证据。已有样本与实验主要使用预建记忆，不因设计补全就成为在线构图成绩。

## 8. 工具与训练形式如何由此导出

工具围绕这些资料提供读取／搜索、查看图像、编辑地图与实体、观察、移动和提交结果。位置估计由状态记录统一保存，地图显示读取该记录；不要同时用另一套标记接口维护独立位置。完整工具定义和 coding 范围见 [Architecture](Architecture.md)。

| 形式 | 初始输入与允许操作 | 输出与核验 |
|---|---|---|
| 简单 QA | 地图、当前图及足够证据，一次给齐 | 输出实体对应、方向、位置更新或局部走法；答案绑定实体与时刻 |
| 查询 QA | 当前信息＋固定资料入口，自主读取／搜索旧文本与图片 | 查证后回答；不能把新采集观察混称已有资料检索 |
| 交互 QA | 当前信息不足，可查询、转向或短移获得新观察 | 用新证据回答；明确问的是初始状态还是新状态 |
| 交互 IA | 局部指令、地图和工具，自主组织查询／观察／动作 | 真实完成接近、对齐或指定穿门事件，文字自称成功无效 |

每条数据保存初始可见资料、工具调用与返回、模型输出及记忆变化；标准答案和几何核验另存。允许直接行动及不同有效操作序列，不靠强制工具顺序制造多轮任务。具体任务簇、信息边界和数据划分见 [Tasks.md](Tasks.md)。
