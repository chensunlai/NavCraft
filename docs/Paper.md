# 论文主线：面向通用视觉导航的空间推理与交互能力学习

更新与讨论归档：2026-10-14。本文完整保存论文动机、数字 Agent 训练经验的迁移、方法路线、相关工作边界、实验设计与写作底稿。研究主线已经确认，具体训练算法和预期收益尚待研究与验证。目标架构、任务数据和实验依据分别见 [Architecture](Architecture.md)、[Tasks](Tasks.md)、[Experiments](Experiments.md)。

拟题：**面向通用视觉导航的空间推理与交互能力学习**

*Learning Navigation-Grounded Spatial Reasoning for General-Purpose Navigation*

**核心主张：通过导航特化空间推理、自主子任务与完整轨迹训练，使模型学会导航需要的空间判断，并在共享 Harness 中自主组织查询、观察和行动，完成不同类型的导航任务。** 最终成果是有实际执行能力和训练收益的 Harness＋模型；原子任务、数据集和能力诊断为这一目标服务。

训练内容保持原来的路线：**通用空间推理 → 导航特化空间推理 → 导航自主子任务 → 完整导航交互。** 重点建设中间两类，完整轨迹训练是确定要做的组成，后续可再采用 OPD 或 RL；这是内容之间的衔接，不要求四个阶段严格串行。多参考系与记忆对应是重要的训练内容，不取代整篇“如何培养通用导航 Agent 能力”的主线。

## 1. 完整研究动机：我们究竟要解决什么

### 1.1 第一层：接上 Harness，并不能让现有基础模型自然获得可靠的导航能力

地图、记忆和工具提供了运行条件，但模型仍然可能不会定位、无法把地图出口对应到当前画面、不能根据运动反馈修正判断。**先有足够强的基础能力，Agent 训练才有可利用的起点；现有模型的导航基础能力还不能被默认视为可靠。**

这里要解决的是：怎样训练模型，使它具备自主完成多种导航任务所需要的能力。数字领域 Agent 的发展提供了训练经验，但迁移到导航时，必须补齐导航所依赖的空间基础；可部署小模型是主要训练对象，这个问题并不限于小模型。

已有导航 Harness 和本项目的模型测试能够支持可行性与不足的观察，不能据此认定强通用模型已经稳定掌握导航。开发阶段发现的问题还需在同一输入、工具和评分协议下验证，并排除地图、接口、上下文和环境故障。

Harness 与训练各有作用：前者提供可访问的空间资料和可执行的操作，后者让模型学会使用这些条件。提供初始位姿、地图或深度会改变任务难度与研究范围，但不会自动解决目标实例对应、可接近方向和行动后的判断更新；减少传感器输入本身也不等于创新。

### 1.2 第二层：导航需要的空间基础，不能完全由一般空间问答替代

导航中的空间推理具有更强的任务针对性，也需要跨更长的时间持续发挥作用。知道“电视在床的对面”只是起点：模型还需要判断眼前是哪一张床、自己位于哪一侧、哪个入口通向目标区域，以及转向或前进后这些关系如何变化。判断正确之后，还必须据此改变观察、查询或运动行为。

例如，指令要求“从卧室进入浴室”。模型即使能在俯视图中指出浴室，也仍可能选错眼前的门、误判自己已在浴室、从错误的一侧接近门口，或者碰撞后重复同样的动作。这里缺少的不是更长的场景描述，而是**将目标、当前观察、空间记忆和行动效果连起来的判断能力**。

| 导航提出的要求 | 与一次给定证据的空间问答有什么不同 | 对训练的要求 |
|---|---|---|
| 任务针对性 | 同一场景，找物体、经过指定入口和返回旧目标需要关注不同关系 | 判断绑定目标、实例与局部可行走法，服务定位、选路、接近和穿门 |
| 跨表示、跨视角的联系 | 当前图、俯视图、历史图像与文字记忆的形式、时刻和覆盖范围不同 | 识别相同实体，把关系转换到相关参考系，综合不同证据形成判断 |
| 随行动变化并持续发挥作用 | 移动后外观、朝向和可见性改变，旧判断仍影响后续决策 | 更新自身位置和目标方向，区分有效记忆与过时结论，利用动作反馈修正 |

因此，需要构造**导航特化空间推理数据**，集中训练定位、对应、局部选路和动作后更新等判断。长程导航提出这些要求，不意味着每条训练样本都必须很长；可以用短历史和局部事件获得密集、可核验的监督，再检验长期使用和跨任务复用。

多参考系与记忆对应使这一层更加具体。例如，历史照片从门的另一侧拍摄，模型需要确认它与当前图中的门是同一实体，再把地图上的路线转为当前朝向下的走法。地图、图片、摘要是信息载体；当前相机、历史相机、地图坐标和物体自身朝向才是不同参考系。文件间有链接，不等于模型已经理解了它们的空间联系。

这些要求不意味着所有现有空间训练都缺少相关内容。已有工作覆盖视频、记忆、参考系和导航定向监督；本文研究怎样围绕导航系统训练和使用这些能力。不能声称首次发现通用空间推理与导航之间存在差距。

### 1.3 第三层：掌握空间判断之后，还需要学习在导航中自主使用

地图让环境布局可访问，记忆让过去的证据可保留，工具让模型能够检索、观察和移动。但工具不会自动决定当前看到的是哪扇门、哪张旧图有帮助、是否应相信已有定位，以及新证据出现后应修改哪一步决策。

这里的“学会用工具”不是输出合法 JSON 或选择正确 API 名称，而是掌握**导航工具背后的空间决策**。例如，调用 `view_images` 的价值取决于是否找到了能区分两个相似房间的证据；调用 `nav_step` 的价值取决于是否把地图路线转成了当前朝向下的有效动作。

**这一层要解决的是：模型会作出空间判断之后，怎样自主组织这些判断，持续完成整个导航任务。** 给齐材料后答对一道题，与实际执行时知道该查什么、该观察什么、何时可以移动，是不同的训练要求；完成一个局部事件，也不保证能在更长任务中持续使用这些能力。

第三层包含相互衔接的三个部分：

1. **导航自主子任务训练：学习局部运用。** 给局部目标和工具，让模型自己组织查询、观察与行动，完成可核验的空间事件，学习何时、怎样使用空间判断。
2. **完整导航轨迹训练：学习组合与持续执行，确定要做。** 使用完整教师交互轨迹进行 SFT／轨迹蒸馏，训练模型在完整目标下切换子目标、衔接局部能力、持续利用空间记忆，并根据反馈调整行为。监督包括真实工具调用及可见回答，工具返回作为条件。
3. **后续 OPD 等执行优化：学习处理自身实际遇到的状态，暂定。** 由学生运行到自己的状态，再由教师提供指导，改善偏离示范后的判断、恢复和继续执行；也可研究利用环境奖励的 RL。OPD 与 RL 分别说明，具体选择和算法留待后续确定。

自主子任务提供集中练习，完整轨迹将能力组合成任务执行，后续优化针对学生自身的执行分布。三者共同属于第三层，不需要另外增加第四层，也不要求每个训练环节分别成为独立创新。局部训练与完整轨迹可以混合或分阶段开展，完整轨迹训练的确定性不等于训练顺序已经确定。

需要区分两种失败：**证据已经充分却判断错误**，主要检查空间理解；**证据不足却不会补证**，主要检查自主获取与使用。增加图片或查询次数不必然修复前者。两类问题都服务于完整导航能力，不将论文缩成记忆检索或参考系问答评测。

### 1.4 为什么还要与完整轨迹训练比较

完整轨迹训练既是本文方法的确定组成，也是必要的强基线；它可以同时包含空间解释、记忆使用与行动。核心比较是：在双方都训练完整交互轨迹的前提下，加入针对性空间推理和自主子任务训练，是否优于把相近预算继续用于完整轨迹。不能预先断言轨迹训练无效，或训练后的模型“只会模仿”。

值得检验的假设是：完整成功轨迹对某些空间依赖的监督可能不够集中，也未必充分覆盖相似实例、证据不足、碰撞和错误定位等状态。一个正确转向可能来自多种判断，仅观察动作匹配无法区分模型是否掌握了这些判断。针对性空间监督能否在相同预算下提供额外收益，需要实验回答。

**工作假设：在完整轨迹训练的基础上，加入导航特化空间推理与自主子任务训练，能够比将可比预算全部用于完整交互轨迹，更有效地建立可复用的导航能力。** 这不是以小模型弱或 Astra 强为前提，也不能仅由原子任务分数提高来证明。项目可以据此推进，但论文不能在实验之前把假设写成结论。

### 1.5 数字 Agent 的训练经验：可以迁移什么，需要补齐什么

可以借鉴的经验有三类：利用底座已有的领域能力；通过交互示范学习如何组织操作；在模型自身执行分布上通过反馈改进。不同系统可能采用轨迹 SFT、直接 RL 或组合方案，并不存在所有数字 Agent 都遵循的固定三阶段。

| 可迁移的经验 | 在导航中的落实 | 需要特别处理的空间问题 |
|---|---|---|
| 强基础能力为 Agent 学习提供起点 | 选择合适视觉语言底座，补齐导航特化空间判断 | 一般图像识别或空间 QA 水平，不等于定位、地图对应和运动后更新可靠 |
| 示范任务执行，而不只监督最终答案 | 保存真实工具调用、反馈和可见回答；训练自主子任务与完整交互 | 查询、观察和运动的价值取决于它们能否改善当前空间判断与任务进展 |
| 在自身运行状态上继续学习 | 收集学生错误与教师接续，或进行 RL／OPD | 区分定位错误、证据不足、通路误判和动作未实现，按实际反馈修正 |

这些训练经验是方法来源，不是本文独占的贡献。导航的具体切入是：**补齐任务相关的空间基础，再训练模型在交互中自主运用，并检验同一能力能否服务不同导航目标。** 文献实例与适用边界归档在第 8 节。

## 2. Introduction 应怎样讲：六段连贯的因果链

**第一段：提出需求，也明确实际问题。** 目标搜索、指令跟随与连续目标导航需要同一模型根据不同目标自主组织行为。已有框架提供了地图、记忆和工具，但接入这些条件并不保证模型能够可靠导航；本文关注怎样训练出可复用于多类任务的导航 Agent 能力。

**第二段：引出训练视角。** 数字 Agent 的经验说明，运行框架之外还需要领域基础与任务交互学习。导航同样需要这一过程，但不能默认通用视觉语言底座已经具备足够可靠的导航空间基础。已有空间监督和导航技能训练是进展，尚需具体讨论其学习内容及跨任务验证范围。

**第三段：解释导航与普通空间任务的差距。** 导航需要的判断具有目标条件、时间连续性和行动后果。例如，从“目标在隔壁房间”到真正通过正确入口，需要完成观察—地图对应、自身定向、门口选择和动作调整；证据不足时还要主动补证。因此，研究重点是空间理解如何在持续交互中支持决策。

**第四段：连接判断能力与自主执行。** 给齐证据后的正确判断，不保证模型能在实际任务中自主找到证据、选择操作和利用反馈。因此，在通用空间训练和完整轨迹训练之间，重点建设导航特化空间推理与自主子任务两类训练内容，分别强化判断及其自主使用。这是我们的组织方式，不能声称已有研究完全没有覆盖中间层。

**第五段：概括完整方法。** 共享 Harness 提供稳定的空间资料、观察和行动接口；配套训练围绕定位、空间对应、局部规划及执行效果组织监督，通过自主子任务和完整轨迹训练，学习局部运用与持续执行。后续可在学生运行状态上采用 OPD 或 RL 继续优化。模型自主组合这些操作，能力分类不被写死为固定专家或执行顺序。具体训练算法成熟后再填入正文。

**第六段：明确验证与产出。** 使用同一模型和主要运行机制，在目标搜索、指令跟随及连续目标任务上评估未见场景表现。主结果是完整导航的成功率、效率和成本；原子诊断、受控变体与消融解释收益来源。最终要交付的是可运行且有学习收益的导航框架与模型。

这六段回答的是“为什么需要这项工作、为什么采用这个方向、最后如何证明”，不按“先测试 Astra，再拆任务”的真实开发经历组织引言。

## 3. 方法如何形成一个整体

### 3.1 Harness：为共享能力提供稳定的运行条件

Harness 负责提供观察、空间资料、历史证据和行动接口；模型决定当前需要读什么、确认什么、往哪里走以及何时修正。定位、规划和执行是可复用的能力类别，不是必须依次调用的多个固定专家。

目标 Harness 采用平面图、实体文本和证据图片相互关联的空间记忆。完整导航默认提供起始位置／朝向提示，之后由模型结合 RGB、动作反馈与历史维护定位和任务判断；原子任务按所训练能力调整初始资料与可用工具。基础墙层和初始资料保持只读，当前实体记忆按任务从允许的预建资料或空状态初始化；模型可依据观察在线建立、修订实体及其位置、连接和证据，并维护自身估计。

模型通过工具按需读取证据、编辑记忆、查看地图、计算和行动；连续目标切换时保留环境认识，更新任务意图。[上下文平时只追加，接近预算上限时统一压缩](Architecture.md#context-management)，避免每轮重组输入。具体工具和空间记忆见 [Architecture](Architecture.md#harness) 与 [SpatialMemory](SpatialMemory.md)。这些是设计约定，不能据此宣称导航效果或训练收益已经验证。

**“通用”应有具体含义：**同一组模型权重、空间表示、工具语义和主要运行循环支持三类任务；任务适配器可以改变目标形式与结束协议。仅接入三种数据读取器不等于通用，也不能为每个基准训练不同模型后仍声称同一策略通用。

训练对象是这个自主组织行为的导航主控。若未来增加低层执行器或并行模型，需要说明各自负责什么、训练了谁；训练可调用的运动模型与训练主控的证据使用和工具决策，是不同的学习范围。训练任务也不能强制每次都查询、标位置或按相同顺序操作；有效的直接行动同样应被接受。

### 3.2 两类中间训练内容：空间判断与自主使用

| 内容 | 输入与输出 | 主要学习什么 |
|---|---|---|
| 通用空间推理 | 给定图像、视频或空间描述，回答关系、方向、距离等问题 | 可利用的基础能力或辅助训练来源；不假设每个底座都要重新大量训练 |
| **导航特化空间推理** | 给定目标、观察、地图、历史或短动作反馈，输出位置、对应、方向更新、局部走法判断 | 从可用证据中形成导航需要的正确判断 |
| **导航自主子任务** | 给定局部目标、初始信息和工具，自主查询、观察或移动，直到回答或完成局部事件 | 决定如何获取、使用和修正空间判断 |
| 完整导航交互 | 给定完整目标，持续交互直到按任务协议结束 | 在完整任务中组合、延续和复用能力 |
| 学生经历与纠错数据 | 从学生实际访问的状态和历史出发，提供有效修正及后续行为 | 在部署分布中恢复和继续执行；可与上述内容结合 |

原称“导航特化子任务”的一类，在本文中称为“导航自主子任务”，强调模型有必要的决策选择。两类中间内容的区别不是轨迹长短，而是前者主要训练给定证据下的判断，后者训练为实现局部目标自主组织操作。

对应的数据形式保留四种：**直接 QA** 使用一次给定输入；**查询 QA** 读取样本开始时已有资料；**交互 QA** 获取新观察后回答；**交互 IA** 执行指令并实际完成局部事件。每个任务簇选合适的 1–2 种形式，不要求做满组合。具体能力与样例由 [Tasks.md](Tasks.md) 维护。

### 3.3 针对性训练与数据组织：需要发展的核心方法

训练对象是“看到了什么空间证据、据此作出什么判断、这个判断应该如何影响行为”。短期能力包括自身定位与定向、短程位姿更新、观察与地图双向对应、局部选路和动作落实；它们可以在同一房间或相邻区域内获得可靠标签和真实执行核验。

一种候选机制方向是：**训练同一实体与空间关系在不同视角、动作前后的正确对应，同时允许新目标或反证改变判断和行为。** 例如，同一物体跨视角仍应对应同一地图实例；自身右转后，目标相对方向应相应变化；发生碰撞后，不能把未实现的位移更新为已发生的位移。保持的是物理身份与有效关系，不是要求不同朝向下输出相同动作。

此前讨论的 [S-Space](https://mirros.ai/blog/s-space) 启发保留为表示层训练的探索方向：是否能让与定位、实例及空间关系有关的表征，更稳定地参与导航决策。它是机制分析的启发，不能当作已经验证的导航训练方案；特征读取、损失函数和优化方式尚未确定，也不能据此推断 Astra 的训练来源。

可围绕同一个局部事件组织不同监督，避免空间题与执行轨迹彼此脱节。例如，目标为“通过地图上的 D3 门”：

| 证据条件 | 空间推理或自主子任务 |
|---|---|
| 当前图与地图已足够 | 找出当前图中对应 D3 的门，判断接近方向；允许直接执行 |
| 证据来自另一视角 | 利用从门另一侧拍摄的历史图，确认实例与当前走法 |
| 关键证据保存在资料库 | 自主检索能区分相似门的证据，再判断或执行 |
| 现有资料确实不足 | 转向或短距离移动，取得能消歧的新观察 |
| 先前位置估计与新画面矛盾 | 检查并修正估计，继续原目标；输入明确标注估计的不确定性 |

这只是候选的数据与验证设计，不是已经确定的训练算法。可以共享物理场景和事件标签，但应接受多个有效查询及动作序列；需要移动的示范必须真实执行，并核验指定开口或局部事件，而不只看教师最后自称成功。

方法贡献可以来自有依据的监督构造、训练组织或专门优化机制，**不要求为区别相关工作临时发明新损失**。若声称新训练算法，应解释它增加了什么约束，并做相同数据上的普通 SFT 对照；若使用普通 SFT，则需要通过数据、课程或交互设计的消融与迁移结果建立价值。增加任务名称或补上常规 RL，都不会自动证明贡献。

### 3.4 第三层的训练落实：自主子任务、完整轨迹与后续执行优化

第二层提供导航特化空间判断的训练；第三层通过自主子任务、完整轨迹和可选后续优化，将这些判断用于完整任务。**完整轨迹 SFT／蒸馏已确定纳入方法，OPD／RL 尚为后续候选。**

| 组成 | 解决什么问题 | 不能由它单独证明什么 |
|---|---|---|
| 导航特化空间推理 | 密集学习局部空间判断、证据对应和动作后更新 | 给定证据下答对，不保证会自主选择操作 |
| 导航自主子任务 | 在局部目标下组织查询、观察、规划与实际执行 | 短任务成功，不保证长程持续使用与跨任务迁移 |
| 完整轨迹 SFT／蒸馏（确定） | 学习在任务进程中何时使用这些能力，以及如何组合和延续判断 | 成功示范未必覆盖学生会遇到的全部错误状态 |
| 后续 OPD 或 RL（候选） | 在模型实际访问的状态中优化能力选择、纠错、持续执行和成本 | 后阶段收益不能倒算为空间训练方法本身的收益 |
| 完整导航评估 | 检验局部能力是否真正迁移到三类任务 | 总成功率变化还需消融解释来源 |

这是各部分的作用分工，不预设唯一训练顺序。可以分阶段或混合训练；实际开发应尽早建立轨迹 SFT 基线，而不是等全部空间任务完成。

RL 可利用环境结果优化策略；若采用 OPD（on-policy distillation），则由教师指导学生实际访问到的状态。具体算法暂不确定，两者也不应混称。在线向 Astra 求助属于另一种推理时协同机制，应单列为可选扩展，主结果首先验证训练后小模型的独立执行。

### 3.5 空间记忆：保留完整研究方向，分清当前范围

空间记忆采用 **以空间实体为中心的平面图＋文本＋视觉证据**。平面图按楼层表达区域、墙体、出入口和主要物体的近似位置；文本记录语义、辨识线索与明确参考系的关系；RGB 图片支持回看与核对。三者通过稳定实体 ID 和图片引用关联，一个实体可有多张证据图，一张图也可支持多个实体。区域不一定是封闭房间，开口不保证可通行，示意 box 不等于精确占据范围。具体形式、字段、示例和读写边界单独归档于 [SpatialMemory.md](SpatialMemory.md)。

已有资料之间的链接为模型提供检索线索；当前新观察中的对象如何对应到地图，仍需模型判断。自身位置、观察对应与局部计划作为运行状态叠加，设计上要求说明依据帧、时刻、参考系与确认状态，允许后续修正。统一关联有助于组织训练与运行证据，但不能单凭文件链接证明模型掌握了跨视角空间推理。

目标 Harness 覆盖三个环节：**构建**——将观察与实体关联、绑定证据并记录位置和关系；**使用**——依据地图定位、检索目标、选择入口和落实路线；**修订**——在新旧证据冲突时更新记录及受其影响的计划。先支持最简局部在线构建与修订；评价应同时考虑记录正确性与后续导航效用，不能用地图好看或描述丰富代替后者。

现有数据和实验主要涉及已有空间记忆的使用和位置估计维护；在线增删实体、更新位置与房间连接及语义修订已纳入目标设计，尚未由现有数据和成绩验证。A05／A06 针对的是观察与既有地图的对应，不能直接称为在线地图构建。长程记忆仍是后续完整任务的需求，但本轮原子任务保持短程范围。

## 4. Astra、数据与能力评测应放在哪里

最初对 Astra 导航和空间组织能力的观察是研究启发，但不是整篇论文必须依赖的论证前提。不同 Harness、输入和协议下的探索性表现不能直接拼成正式成绩，也无法说明它究竟训练过什么数据。

用户曾在自己的测试中观察到 Astra 达到 90+ SR，并能依靠上下文组织空间信息；该观察保留为研究来源，不写成本项目已经完成的规范跨任务成绩，也不推广为所有强通用模型都能可靠导航。本文目标不是分析 Astra 本身、复原其训练配方，或把大小模型协同作为主贡献。

Astra 或其他强模型可以用于开发参考、同协议下的参考模型，以及候选教师。教师回答与交互必须经过几何、图像或真实执行核验；教师弱的必要任务仍值得保留，先检查可观测性和标签，再选择其他可靠监督来源。

**任务的必要性来自导航需要完成的判断，任务的训练价值来自训练后的导航收益。** “Astra 都强、小模型都弱”只能描述表现差异；不能以此独立证明任务设计合理或某项训练有效。

评估集与训练集可以共享任务定义和构造方法，但必须分开场景、种子和轨迹来源；同一状态的单帧／全景、改写题和正反对应题不能跨划分泄漏。四种形式——直接问答、检索问答、主动感知问答、局部指令执行——分别检验充分证据下的判断、历史利用、新证据获取和真实执行，不能靠强制多轮包装主动能力。

## 5. 预期贡献及成立条件

以下是预期贡献，论文定稿时只保留已经实现并有证据支撑的部分。

1. **面向导航 Agent 的能力训练方案。** 以导航特化空间推理与自主子任务连接基础能力和完整执行，学习目标、观察、判断及行动效果之间的联系。通过预算可比的轨迹基线、训练内容消融和迁移验证建立价值；如提出新优化算法，再做同数据普通 SFT 对照。
2. **支持多类任务自主执行的导航 Harness＋模型。** 在共享表示与工具下组织查询、观察、定位和动作，并在完整导航中表现有效。工程封装或工具数量不是单独的算法创新；核心是训练后的模型能够怎样使用这些条件。
3. **从原子能力到完整导航的验证与数据支持。** 构造可核验的局部任务和交互数据，通过跨任务、未见场景与受控分析解释训练的作用。数据是方法的支撑产物，不能成为整篇论文唯一剩下的成果。

已有工作覆盖导航定向空间训练、技能调用、主动查询和记忆使用；这些先例限制具体新颖性声明，但不等于整条能力学习路线已经充分解决。本文不以“此前无人训练导航 Agent”立论，也不以“别人是工作流、我们是 Agent”排除比较。区别落实在训练内容、模型自主使用能力和跨任务复用的证据上。

## 6. 实验怎样把论文主张证明出来

核心比较使用相同基础模型、Harness、教师与场景来源，尽量对齐优化步数、训练 token、教师调用及环境交互成本。无法同时精确匹配的成本分别报告，不用“等样本数”代替全部预算控制；轨迹基线保留可导出的教师空间解释和工具调用，不人为删减使其变弱。

| 组别 | 训练设置 | 用于回答 |
|---|---|---|
| B0 | 基础模型＋共享 Harness | 仅运行支持能达到什么水平？ |
| B1 | 完整教师交互轨迹 SFT | 直接训练轨迹已经能解决多少问题？ |
| B2 | 从 B1 继续等预算轨迹训练 | 额外收益是否只是训练更多？ |
| B3 | 从 B1 加入通用空间训练 | 导航针对性是否必要？ |
| B4 | 从 B1 加入导航特化空间推理，使用普通 SFT | 导航针对性空间判断的监督有多少作用？ |
| B5 | 从 B1 加入导航自主子任务，使用普通 SFT | 自主组织局部交互的监督有多少作用？ |
| B6 | 从 B1 加入两类中间内容，使用普通 SFT | 两类内容是否互补，能否迁移到完整任务？ |
| B7（条件项） | 与 B6 使用相同数据，采用所提专门训练算法 | 若提出新算法，是否有独立于数据内容的收益？ |
| B8（若采用后续优化） | 在选定方案后加入 OPD 或 RL，并给关键基线可比的后阶段预算 | 执行优化带来多少收益，前置训练是否仍有帮助？ |

B2–B6 的新增训练预算应可比；B6 不能直接使用 B4、B5 两倍的数据和计算后，把增益全部归因于互补。表格用于拆解贡献，不强制各实验必须采用先 B1 后追加的课程；若混合训练更合适，应对齐对应比较。新增纠错状态、视角、教师调用及 RL／OPD 预算分别报告。

**两类比较分开做：**与 AgentVLN 等相关系统比较完整导航效果，明确各自输入和执行器；在本项目同一 Harness 内改变训练，检验方法收益。直接比较不同论文的成功率，无法隔离预构建地图、位姿、深度、动作粒度或低层规划器的影响。

主要结果在未见场景的目标搜索、指令跟随和连续目标任务上报告成功率、路径效率、失败恢复与成本；连续任务保留全部预定目标作为适当分母。当前自建 HM3D 指令只能支持该设置的结论，不能代替正式 VLN-CE；地图先验、位姿条件、动作和成功判据必须说明，细节见 [Experiments](Experiments.md#protocol)。

机制分析围绕三个问题展开：

- **空间判断是否影响行为？** 在受控状态中改变目标、朝向、实例或碰撞反馈，检查定位、查询和动作是否随有效证据变化。
- **交互是否带来独立价值？** 先在证据齐全条件下检查判断，再将关键证据放到可查询资料或需要移动的新视点，检查自主获取与使用。比较自动提供、教师选取及模型自主选择的证据，记录实际图片和动作预算。初始证据已充分的样例不能证明主动补证必要。
- **收益能否持续和复用？** 用同一检查点评估多类任务，留出场景以及能力、目标表达和证据条件的部分组合；检查目标切换、长轨迹及压缩之后的表现。多接几个 benchmark 不自动证明能力迁移；Harness 改动和模型训练的收益分别报告。

原子分数与导航表现相关只能提供诊断线索；给模型真值定位的干预只能用于上界分析。最终仍需冻结 Harness、只改变训练，在完整导航中验证。原子能力提高但导航不变时，应检查任务与决策是否脱节、运行时是否使用了能力，以及是否存在其他瓶颈。

以下为研究方案摘要，尚不是报告已完成训练结果的最终摘要：

> 地图、记忆和工具为视觉语言模型提供了导航的运行条件，但接入这些条件并不保证模型能够可靠地完成不同类型的导航任务。导航依赖具有任务针对性、能够联系当前观察与历史空间资料、并随行动持续更新的空间判断；同时，模型还需自主决定如何获取和使用这些判断。本研究面向地图辅助的通用视觉导航，在通用空间训练与完整轨迹训练之间，重点设计导航特化空间推理与自主子任务两类训练内容，并结合共享 Harness、完整教师交互及后续执行优化，研究如何建立可复用的导航 Agent 能力。我们将用同一模型与主要运行机制完成目标搜索、指令跟随和连续目标导航，通过预算可比的完整轨迹基线、训练内容消融和跨任务验证，检验空间能力是否被自主用于实际导航。

贡献段在有结果后补入具体训练机制、主要成绩和迁移发现。Astra、在线大小模型协同及某一种候选损失不作为摘要必须出现的内容。

### 8.1 数字 Agent：训练经验有依据，但没有唯一配方

| 工作与日期 | 已核验事实 | 对导航的借鉴 |
|---|---|---|
| [SWE-smith，2025-04-30](https://arxiv.org/abs/2504.21798)；[官方训练流程](https://swesmith.com/guides/train_swe_agent/) | 在可执行环境中生成专家工具轨迹，经测试筛选后用于 SFT | 保存真实交互与反馈，执行核验后再作为示范 |
| [DeepSWE，2025-07-02](https://www.together.ai/blog/deepswe) | 从已有 Qwen3-32B 出发，在 R2E-Gym 中仅用 RL 进行 Agent 后训练，以代码测试提供奖励 | “纯 RL”仍以已有领域能力为起点；轨迹 SFT 不是所有系统的必经阶段 |
| [OpenWebRL，2026-06-01](https://arxiv.org/html/2606.02031v1) | 412 条教师轨迹初始化后，在约 2.2K 个真实网页任务上进行当前策略采样与多轮 GRPO | 学生需面对自身行动造成的后续状态，并通过实际任务反馈学习 |

可迁移的是示范、工具交互和执行反馈的训练机制；导航所需的空间内容仍需针对性设计。不能把“基础训练＋示范＋RL”写成文献已经证明的普遍最佳顺序，也不能把借用通用训练机制当作独立首创。

### 8.2 AgentVLN：承认重合，保留完整研究问题

[AgentVLN，2026-03-18](https://arxiv.org/html/2603.17670v1) 明确讨论空间感知不足、二维／三维表示不匹配和尺度歧义，并训练技能调用、目标定位、主动几何查询及纠错。不能把这些内容说成本文首次提出。

其训练围绕路点选择、局部目标定位和细动作恢复组织，存在明确阶段结构，但模型仍参与技能选择。主要定量验证集中于 R2R-CE／RxR-CE；不能将“阶段约束较强”改写成“完全没有自主性”，也不能将缺少跨任务验证改写成“无法通用”。[补充材料 §4、§8](https://github.com/Allenxinn/AgentVLN/blob/main/assets/Supplementary_Materials.pdf)

**本文保留的研究重点：通过导航特化空间推理与自主子任务训练，建立能够跨目标形式复用的导航能力。** 当前观察、地图、跨视角历史和动作反馈的联系，是具体训练内容。区别需要通过训练设计与迁移实证建立，不依赖把 AgentVLN 排除在 Agent／Harness 之外。

公开边界单独记录：官方数据卡注明 QD-PCoT 部分仍待开源，不能因为公开代码缺少完整查询流程就断言论文没做。[数据卡](https://huggingface.co/datasets/allenxinn/AgentVLN-Instruct)

## 9. 研究依据与推进顺序

现有四个场景的空间资料，以及 28 条原子展示样例／58 条逐决策记录，可用于检查任务是否清楚、证据是否充分。任务设计为九簇，A09 尚未构建；展示数据来自 25 条 Agent 辅助构造和 3 条混合修订。这些材料尚不能证明空间训练、RL／OPD 或泛化收益。

探索性实验中的反复碰撞、位置判断未及时更新、错误摘要延续等现象可用于选取诊断；显式地图未更新不等于模型没有内部定位。原始证据与限制见 [Experiments](Experiments.md)，结论仍需受控实验支持。

<a id="plan"></a>

| 近期阶段 | 要完成什么 | 推进依据 |
|---|---|---|
| 确定研究条件 | 明确输入、工具、空间记忆和评分，收集可核验的教师交互 | 条件明确、证据充分，可以分析模型的判断与行动 |
| 尽早建立轨迹 SFT 基线 | 用小规模完整教师轨迹训练，在同一 Harness 中评估 | 明确已有能力和稳定缺陷，避免凭设想投入大量数据 |
| 验证两类中间训练 | 先选一两类局部事件，同时准备给定证据的空间判断与有真实选择的自主子任务，比较继续轨迹训练与两类训练的作用 | 判断、自主使用和完整导航的收益能被区分，再扩大数据与发展机制 |
| 完成方法与完整验证 | 完善训练内容消融；若采用 OPD／RL 或提出专门算法，增加对应对照 | 支撑论文主张后再扩大数据与任务范围 |

Harness 与训练任务可以迭代，但一轮对照内必须冻结条件。这里保留完整论文目标，不要求现在同时完成在线构图、长期记忆训练和所有消融。

早期不必先建成一套庞大 benchmark，也不必等 Astra 在所有任务上表现完美。先保证少量场景的资料和交互可信，采集可核验示范，尽早开展小规模训练与局部诊断。诊断服务训练决策，不以“教师全强、学生全弱”作为任务价值证明。

## 10. 本轮讨论的确认项与未定项（2026-10-14）

| 状态 | 归档结论 |
|---|---|
| 已确认：研究目标 | 提出可运行的通用导航 Harness＋经过训练的模型；能力评测、数据和教师分析为此服务 |
| 已确认：三层逻辑 | 接上 Harness 不保证可靠导航；一般空间问答不完全覆盖导航所需空间基础；掌握判断后还需学习自主使用 |
| 已确认：训练内容 | 在通用空间推理与完整导航交互之间，重点构建导航特化空间推理和导航自主子任务；顺序与配比可迭代 |
| 已确认：具身空间特点 | 目标针对性、不同表示／视角／时长／范围的证据联系，以及随行动变化的持续更新 |
| 已确认：AgentVLN 的位置 | 强相关训练先例与比较对象；承认重合，保留本文对能力学习与跨任务复用的完整研究目标 |

| 已确认：Harness 目标范围 | 使用预建记忆、局部在线构建与修订及导航辅助能力；基础墙层只读，具体接口见架构与空间记忆文档，尚未作为已实现或已验证贡献 |
| 待设计 | 专门的空间训练算法、是否引入表示层约束、数据配比与课程、后续 RL 或 OPD 的具体方案 |
| 待验证 | 两类中间训练是否优于预算可比的完整轨迹训练，是否互补，是否提升自主使用与跨任务迁移 |
| 后续扩展 | 长期记忆专项训练、推理时大小模型协同；不纳入当前已实现贡献 |

不再沿用的表述：此前没人训练导航 Agent；强通用模型接上 Harness 就已经可靠；训练轨迹必然只会模仿；AgentVLN 完全没有自主性；多参考系对应取代全部主线；每个训练阶段都必须原创；必须另造一个损失函数才能形成论文。

维护约定：**可以合并重复文档，不能把研究动机、差距分析、方法理由、贡献成立条件和完整验证逻辑压缩成仅有进度的摘要。** 本文持续维护论文核心；架构与空间记忆、任务设计、实验依据分别由对应文档维护。
