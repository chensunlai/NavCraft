# 空间任务与数据

更新：2026-10-14。任务定义、场景素材和数据构造方法统一维护在本文；图文例子见[样例图册](examples/README.md)。

## 任务范围与形式

当前原子任务围绕五项能力设计：**N1 自身定位与定向、N2 局部规划、N3 动作控制、M1 观察→地图、M2 地图→观察**。任务限定在同楼层、一个房间或相邻区域，解决一次定位、对应、选路或局部运动事件。暂不涉及全局探索、长程记忆、在线重建和 STOP 判断；[Harness 的在线构图设计](SpatialMemory.md#map-building)不表示本文已经构建对应训练数据。

| 形式 | 输入和允许的操作 | 要求产出 |
|---|---|---|
| F1 直接问答（简单 QA） | 一次给出图片、地图和必要短历史，不调用工具 | 答案、对应关系、位姿、局部目标或待执行动作 |
| F2 检索问答（查询 QA） | 从样本开始时固定的资料库读取／搜索文本、查看图片，允许裁剪／拼图 | 查证后的回答；可记录并绘制自己的定位判断 |
| F3 主动感知问答（交互 QA） | 可以检索、`nav_observe` 或有限 `nav_step`，采集新证据 | 新证据支持的回答；移动本身不是终点 |
| F4 局部指令执行（交互 IA） | 可以查询、观察和移动 | 环境中实际达成指定事件，文字自称完成不算成功 |

读取已有全景属于 F2；重新采集全景或转向获得新 RGB 属于 F3／F4，即使没有净位移。工具可用不等于必须调用，初始证据已足够的题目不能用来证明主动查证能力。

四种形式与完整导航采用一致的[空间表示和工具语义](Architecture.md#tool-design)，区别在于初始证据、可用操作与结束条件。这样，局部任务训练的判断和工具用法可以在完整导航中继续使用，不要求所有任务提供相同资料或固定调用顺序。

## 九个任务簇

S 是当前单张 RGB，P 是同一位置、相对机体朝向标定的六个水平视图。已构建的每个“任务簇 × 形式”组合各有一个 S 和一个 P 样例，使用不同有效种子。A09 保留新增编号，置于定位与规划之间。

| 簇／能力 | 输入 → 要求输出 | 主要形式；现有条数 | 例子与构造／评分重点 |
|---|---|---|---|
| **A01 自身定位与定向** · N1 | S／P＋地图＋可选候选位姿 → 自己的区域、位置与朝向 | F1、F3；4 | 从门侧看到浴缸，选择与观察相符的候选位姿；不能把看到浴室等同于身处浴室。隐藏当前位置真值箭头，用私有位姿核验。 |
| **A02 短程位姿更新** · N1 | 原始起点提示＋真实短动作及前后观察 → 末状态位置与朝向 | F1；2 | 前进两步、右转一次后选末位姿。动作和帧来自同一真实执行；碰撞时依据实际反馈，不累加计划位移。 |
| **A09 联合空间问答** · N1＋M2，出口题含 N2 | 地图＋S／P＋空间问题＋明确的定位辅助条件 → 目标相对方向或出口走法 | F1、F2；**待构建** | “长凳在我的哪个方向？”“客厅在我哪侧？”“怎么离开这个房间？”方向绑定题目时刻的机体朝向；房间指定参考区域，接受多个有效出口。 |
| **A03 局部子目标与通路选择** · N2 | S／P＋起点提示＋相邻区域目标＋地图／查询资料 → 下一局部子目标或开口 | F1、F2；4 | “进入 R03 应经过哪个开口？”查询地图后选择 D03。目标尚未落实为动作；离线核验连接与局部可达性。 |
| **A04 局部动作选择与执行** · N3 | S／P＋已指定的可见目标／门口＋动作规格 → 下一动作，或实际对齐、接近、穿门 | F1、F4；4 | 门口已指定，修正朝向后穿到门内侧。比较实际效果，允许不同有效动作串，不要求逐 token 模仿教师。 |
| **A05 观察→俯视图** · M1 | S／P 中指定实例＋地图候选／证据 → 对应地图实体或区域 | F1、F2；4 | 将 RGB 中黄色框 T 对应到地图上的长凳；借助它与床的关系消除同类候选歧义。实例标记需真实可见性核验。 |
| **A06 俯视图→观察** · M2 | 地图指定实体＋S／P＋定位辅助条件 → 画面实例、区域或全景视角 | F1、F3；4 | 找到地图指定的餐椅；交互版取得新 RGB 后选择候选框。目标遮挡或在视野外时允许“不可见”，不能只投影 box 当真值。 |
| **A07 地图路线落实为行动** · M2＋N3 | 地图局部路线／节点＋S／P＋起始提示 → 对应到当前视野并实际执行 | F4；2 | 沿图上短路线对准门口并通过指定 D03。独立记录视觉对应和运动结果，不能用“找对门”代替“穿对门”。 |
| **A08 观察目标落图后选择走法** · M1＋N2，执行含 M2／N3 | 目标参考图＋当前 S／P＋地图＋起始提示 → 目标对应、通路选择，或实际进入局部区域 | F2、F4；4 | 从入户门、玄关桌与台灯辨认目标区域，再选择或经过 D05。目标对应与走法分别评分，参考图朝向可与机器人不同。 |

A03 选择“去哪里”，A04 执行已确定目标；A07 已给定地图目标，A08 先从观察确定目标。A05／A06 读取已有空间记忆，不代表已经会在线建图。辅助定位、候选框和路线都是显式输入条件，不能据此宣称无辅助的完整能力。

## 样本边界与独立核验

- **观察条件：**S 起步后主动取得 P，记录为观测扩展；若固定资源库已有同点完整全景，不计为严格单视图条件。全景角度是相对朝向，不泄漏世界朝向。
- **答案锚点：**记录问题对应的 `frame_id`、时刻和对象。未另说明时回答最新状态；现有 A01 交互版明确问初始位姿。A05 换视点后仍匹配原指定对象；A06 回答新画面时绑定新帧，不能按旧图评分。
- **公开／私有：**每条任务声明初始资料、可读资源和工具范围；读取、搜索、绘图与 Python 均遵守同一范围。公开地图、描述和参考证据可以作为先验；当前位置真值、语义掩码、出题上下文及标准答案不向模型开放，私有核验和 IA 终止判定可使用。A01 隐去当前位置箭头且不能由工具恢复，A02 只给原始起点。查询帧用中性文件名，避免房间名直接泄漏答案。若卡片直接给出被问关系，该题只能作为资料检索，不能计作视觉空间推理。
- **几何与歧义：**检查实例身份、可见性、坐标转换及区域关系；示意图中心不是精确表面。方向和位置使用容差，对称／遮挡样本允许事先核验的等价答案或补证，不能罗列全部候选得满分。
- **实际事件：**“穿过 D01”要求真实轨迹跨过指定开口并抵达另一侧；“对准门口”要求朝向容差及目标可见性。IA 达成事件后自动结束，并停止剩余批次动作；这不改变完整导航的 `nav_finish`／STOP 语义。三类 QA 则以最终回答提交结束，正确性另行核验。均不逐步公开正确方向、私有分数或距离梯度。
- **数据划分：**同一种子的正反对应题、S／P 和相邻视点放在同一划分；泛化评估另按场景划分。形式间证据与行动预算不同，不能直接以成功率高低解释能力差异。

有效对照优先改变一个变量：同场景换目标、同目标换朝向、同类别换邻接布局、同动作换自由移动／碰撞反馈。主动感知样本需核验“初始存在歧义，新增证据能够消歧”，不靠强制调用次数制造多轮任务。

## 场景地图与可用素材

当前场景表示由 **Astra 辅助构建，经多轮渲染复查和修正**，用于提供可靠的任务素材。规则承担测量、绘图及一致性检查；模型依据 RGB、语义和几何证据解释门洞、扫描缺损并简化家具。直接投影／过滤曾造成碎裂和封门，因此这些素材的构建过程不作为已经验证的通用自动构图算法。

归档路径保留数据集完整子路径：原始场景在 `data/nas/scene_datasets/<dataset>/<split>/<scene>/`，场景表示在：

```text
data/scene_maps/<dataset>/<split>/<scene>/
├── floor_plan.png         # 直线墙体、房间／楼梯分区、主要物体 box
├── scene_description.md  # 房间、物体、关系与证据引用
├── evidence/             # 实际 RGB 证据
├── evidence_rooms.jpg
└── raw/                  # 墙／房间／门／物体 JSON、图层、来源和复查记录
```

开放区域不人为加墙，L 形家具可组合多个 box；检查入口、灰区、孤立房间、跨层连接、家具穿墙／越界和合理嵌套。地图、实体 ID、文字和证据须保持一致；未解决问题保留在核查记录中，不能为连通凭空开门。

以下为 2026-10-12 归档核查快照：四个场景共 210 个物体、533 条 RGB 证据，证据引用可访问，已有地图校准资料；这不代表所有几何／连接均已实测。

| 场景 | 分区／物体／证据数 | 直接影响出题的条件 |
|---|---|---|
| QaLdnwvtxbs | 8／40／120 | 7 个内部开口标为 RGB＋局部 NavMesh 已核验，3 门关闭；40 个物体均有关联源实例，78 条证据标为实例可见。现有展示集唯一场景。 |
| kfPV7w3FaU5 | 15／61／145 | 2 层；13 门开放、4 门关闭、1 处视觉开放但 NavMesh 不连通；物体尚无统一源实例关联。 |
| 5cdEh9F2hJL | 12／63／150 | 63 个物体均有关联源实例，126 条证据标为实例可见；12 个连接仍是未核验的示意邻接。 |
| 4ok3usBNeis | 18／46／118 | 3 层；21 门和 3 处开放连接；116 条证据有位姿，但格式不同，物体尚无统一源实例关联。 |

`raw/rooms.json`／`regions.json`／`doors.json` 提供候选连接，`objects.json`／`evidence.json` 提供实例证据，Habitat 新渲染和真实短动作提供独立查询图与私有标签。门口仍须按当前机器人尺寸、相机和离散动作实测；地图空白不是可通行证明。统一位姿字段、四元数和坐标约定后再扩场景；`target_pixels` 只是像素数量，不是框或 mask。

## 已交付展示集

入口：[完整交互浏览页](../data/atomic_spatial/demo-20261012-v1/index.html)、[图文例子](examples/README.md)、[验收清单](../data/atomic_spatial/demo-20261012-v1/validation.json)。

**28 条样例、58 条逐决策记录；F1／F2／F3／F4 分别为 12／6／4／6 条，覆盖 A01–A08 的 14 个组合。** 6 条 IA 均真实穿越指定开口，移动约 1m、4–6 个动作；独立重放逐步位置误差为 0。A09 尚待构建。

**来源为 25 条 Agent 辅助构造、3 条混合修订，共 20 次 high-reasoning 请求。** 未修订教师轨迹没有作为最终干净示范保留；审题耗尽预算、定位／对应错误和解释不准确等原始输出均留存。这是可核验的数据形态展示，尚无训练／测试划分，不报告教师成功率或训练收益；部分交互题初始证据已足够，不能用来证明主动感知必要性。

```text
data/atomic_spatial/demo-20261012-v1/
├── index.html                 # 逐轮图文；私有验收材料仅在审阅区展示
├── manifest.jsonl             # 任务、形式、观察条件、来源和修订
├── conversations.jsonl        # 完整可见角色消息、图片、工具定义／调用／返回
├── decisions.jsonl            # 当时实际上下文 → 当前可见模型输出
├── requests.jsonl             # 请求计数、用途与 reasoning 参数
├── validation.json            # 覆盖、来源和请求统计
├── samples/<id>/
│   ├── task.json              # 公开题目、初始固定资源表
│   ├── selected.json          # 入选记录与修订原因
│   ├── attempts/              # 实际 teacher／agent_revision 交互
│   └── private/               # 位姿、标签、掩码、审查、修订和重放
└── private/requests/          # 原始请求响应与未入选失败
```

监督目标是可见回答与有效工具调用；用户消息、图片和工具反馈是条件。私有真值、出题内容、未来帧和服务端不可读 reasoning 均不进入 SFT。失败调用可保留为纠错上下文，但不作为正向模仿目标；修订后的有效行为须标明来源。浏览与训练数据使用同一入选记录。

## 构建与下一步

流程：规则采样有效种子与私有标签 → 独立模型上下文审题 → 真正运行工具采集 → 几何／图像／动作重放验收 → 有记录地修订 → 导出。扩展场景时，重新检查可见性、实例关联和局部可达性，不能仅替换场景名称就沿用标签。

展示集采集使用 DeepSeek `deepseek-v4-flash-vision`，推理强度为 high，请求预算为 200 次，实际来源与调用数见上文。F1／F2／F3–F4 的决策预算分别为 1／4／12，运动上限为 24 个原子动作、4m。

相机与运动条件沿用 ObjectNav visual 设置：640×480、水平视场角 79°、相机／机器人高 0.88m、半径 0.18m、前进 0.25m、转向 30°、关闭碰撞滑动。语义资产只用于私有可见性检查和出题标记；观察、动作与地图之间须使用一致的坐标约定。

接下来先补 A09 的方向／出口题，筛出真正需要新证据的 F3 样本；再加入换目标、换朝向、相似实例与碰撞配对。完成逐场景坐标、实例和门连接适配后，按种子／场景划分数据，再评估自动采集质量与训练收益。
