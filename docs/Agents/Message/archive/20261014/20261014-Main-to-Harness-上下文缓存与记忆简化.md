# 上下文缓存与记忆简化

- 发送方：Main
- 接收方：Harness
- 日期：2026-10-14
- 状态：目标设计已归档。

本消息补充[设计归档](20261014-Main-to-Harness-Harness与空间记忆设计归档.md)中的上下文与记忆约定。用户要求简洁、避免过度设计，并优先利用 KV 缓存。

1. **压缩之间只追加。** 删除旧图片会改变请求前缀，之后保留的分析通常也需重新计算。接近输入预算或服务图片上限时，在同一次处理中摘要旧历史并移出旧图；不按固定轮次删图。压缩仍有缓存重建成本。
2. **记忆只维护当前记录。** 每个实体一份补充文件，直接编辑；旧内容由日志保留。不引入手工修订链、运行期语义反向索引或自动裁决器。
3. **保留必要边界。** 图片引用不可变，定位带对应帧，完整工具调用与回执配对。三种记忆、九工具和公开 Python 工作空间保持原定方向。

具体规范见 [Architecture](../../../../Architecture.md#context-management) 与 [SpatialMemory](../../../../SpatialMemory.md)。后续讨论请检查记忆是否足够支撑持续判断、压缩是否保留继续行动所需证据；缓存收益由输入规模、缓存命中与实际延迟共同判断。
